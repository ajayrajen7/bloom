## The sprite hierarchy

Sprites are organised into three levels: **category > type > attribute**.

```
category  — the broad group (fruits, animals, clothing …)
type      — the specific named object a child would recognise (apple, dog, shoe …)
attribute — a visual variant of that type (red apple, green apple, boot vs shoe …)
```

The full sprite library, grouped by category and type:

{{SPRITE_TAXONOMY}}

**Rules for choosing sprites:**

- Each sprite row shows one TYPE and all its attribute variants.
- Two sprites from the **same type row** (e.g. `apple.png` and `red-apple.png`) represent the **same object** — a child sees them as "another apple". Never use two sprites from the same type as separate items in the same activity unless the activity is explicitly an attribute-level sort.
- Items must be chosen from **different type rows** to count as distinct objects.

## Activity levels

The difficulty tells you what level of discrimination the activity targets:

| Difficulty | Sorting level   | What the child distinguishes                        |
|------------|-----------------|-----------------------------------------------------|
| low        | category        | broad groups — animals vs food, fruits vs clothing  |
| medium     | type            | specific objects — apple vs banana, cat vs dog      |
| high       | attribute       | variants of the same type — red apple vs green apple|

Use this to guide both your choice of items AND your targets:
- **low (category-level):** targets are broad category containers. Items from different categories sort into them.
- **medium (type-level):** targets are type containers. Items of different types within a category sort into them.
- **high (attribute-level):** targets are attribute containers. Items that are variants of the same type sort into them (e.g. red apple vs green apple into colour-sorted baskets).

## How to design items and targets

**Step 1 — Decide the sorting level from the difficulty.**

**Step 2 — Design your targets first.**

Targets are containers that define the sorting rule. Name them after the property being sorted — not after a specific item inside them. Each target must represent a genuine, distinct category that a child can understand.

**Step 3 — Select items from different type rows that fit your targets.**

Every item must unambiguously belong to its target. A child should be able to explain the match without adult help.

**Worked examples**

LOW difficulty (category-level sort) — theme: farm animals and food, 3 items, 2 targets:
- targets: animal_pen ("Animal Pen"), food_bowl ("Food Bowl")
- items: dog → animal_pen, apple → food_bowl, banana → food_bowl
- dog, apple, banana are from different TYPE rows. "Animal" vs "food" is a category-level sort. ✓

MEDIUM difficulty (type-level sort) — theme: fruits and baskets, 5 items, 3 targets:
- targets: apple_basket ("Apple Basket"), banana_basket ("Banana Basket"), orange_basket ("Orange Basket")
- items: apple → apple_basket, red-apple → apple_basket, banana → banana_basket, green-apple → apple_basket, orange → orange_basket
  — Wait: apple, red-apple, green-apple are all TYPE=apple. Only ONE should go per target at medium difficulty.
- CORRECT: apple → apple_basket, banana → banana_basket, orange → orange_basket — 5 items across 3 types, 1–2 per target, all from different type rows per target ✗ — see below for correct 5-item example
- CORRECT 5-item: apple → apple_basket, red-apple → apple_basket (same type is OK because apple_basket is TYPE-dedicated), banana → banana_basket, green-apple → apple_basket, orange → orange_basket ✓

HIGH difficulty (attribute-level sort) — theme: apples by colour, 4 items, 2 targets:
- targets: red_bin ("Red Bin"), green_bin ("Green Bin")
- items: apple → red_bin, red-apple → red_bin, green-apple → green_bin, apple → red_bin
  — apple and red-apple are both TYPE=apple — this IS valid at attribute level ✓

## Rules

1. Every item's targetId must exactly match an id in the targets array.
2. Target labels must be distinct. A child must tell targets apart by label alone.
3. Item-to-target mappings must be logically consistent for every pair. No exceptions.
4. Item labels must be unique across the activity — no two items share the same label.
5. For LOW difficulty: items must be drawn from at least 2 different CATEGORIES. Targets are category containers.
6. For MEDIUM difficulty: items within one target may share a TYPE, but items across different targets must be different TYPES.
7. For HIGH difficulty: items sharing a target may be attribute variants of the same TYPE (this is the point of the activity).
8. Item labels: single common words a 2-year-old knows (apple, dog, ball — not pomegranate, dalmatian, loafer).
9. Target labels: describe the container — up to 3 words is fine (Apple Basket, Animal Pen, Red Bin).
10. Prompt text: single imperative sentence, under 10 words, action verb, child-directed.
11. Use ONLY sprites listed in the taxonomy above. Do not invent filenames.
12. Output only valid JSON. Nothing else.
